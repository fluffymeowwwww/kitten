# 小红书小工具开发规范（硬性约束）

> 来源：小红书科技《「小工具」上线 · vibecoding 2.0 内测指南》（2026-09-09 微信收到，PDF 已全文读取）
> 本项目所有小工具开发**必须遵守**以下规范，违反任何一条会导致审核拒绝或线上不可用。

## 一、提审与挂载流程

1. PC 端登录创作者服务中心：creator.xiaohongshu.com
2. 左侧菜单 → **Builder Hub → 小工具**
3. 新建小工具：填写名称、简介、图标；产物可贴 vibecoding 平台链接或直接上传 zip 包
4. 上传产物包 → 完成配置 → **提交审核**
5. 审核通过后：移动端发笔记 → 编辑页底部「挂件/组件」→ 选「小工具」挂载
6. 读者在笔记内点击即可直接使用，无需跳出 App

## 二、容器硬性约束（开发红线）

### 禁止项（任何一条都不能出现）
- ❌ **一切网络请求**：fetch / XMLHttpRequest / WebSocket / SSE / EventSource —— 完全离线，所有资源必须打包在包内
- ❌ **内联 `<script>` 标签**：JS 必须外置为 .js 文件
- ❌ **内联事件绑定**：`onclick` / `onload` 等 HTML 属性 —— 一律用 `addEventListener`
- ❌ `eval` / `new Function`
- ❌ WebAssembly
- ❌ Web Worker
- ❌ iframe（嵌套页面）
- ❌ WebGL 加载外部纹理（WASM 相关调用不可用）

### 允许项
- ✅ 纯 HTML / CSS / JS，完全离线自包含
- ✅ Canvas 2D 全功能
- ✅ WebGL 纯渲染（shader、内置几何均可）
- ✅ 摄像头 / 麦克风（需用户授权，仅本地处理）
- ✅ 文件选择器：**仅限图片和视频**
- ✅ localStorage / IndexedDB 本地持久化（按小工具隔离，不同工具不共享存储）
- ✅ CSS 动画 / requestAnimationFrame / Web Audio（本地合成）

### 包内允许的文件类型
| 类型 | 扩展名 |
|---|---|
| 页面与代码 | .html / .css / .js |
| 静态资源 | 图片（png/jpg/gif/webp/svg） |
| 字体 | .woff / .woff2（不可用系统字体之外的 ttf/otf） |
| 数据 | .json |

## 三、对本项目（猫咪抽卡小工具）的直接推论

1. **猫咪数据必须在打包时固化**：关系表数据导出为包内 .json，无法运行时拉取更新 → 每次数据变更需重新打包提审（或只更新内容版本）
2. **猫咪照片必须打包进包内**：不能用外链图床
3. **抽卡次数/已收集状态**用 localStorage 持久化，用户可长期留存
4. **无分享链接能力**：引导领养的联系方式只能以文本/图片形式静态展示在卡片上
5. **文件体积需控制**：照片多时注意 zip 总大小（长图猫咪照片建议压缩到合理分辨率，视觉宽 750~1125px 足够）
6. **JS 全部外置 + addEventListener**，构建后需自查无内联 script / onclick / 网络请求

## 四、自查清单（提审前跑一遍）

- [ ] 全局搜索 `fetch(` / `XMLHttpRequest` / `WebSocket` / `EventSource` → 必须为 0 处
- [ ] 全局搜索 `eval` / `new Function` / `Worker` / `WebAssembly` / `iframe` → 必须为 0 处
- [ ] HTML 中搜索 `<script>`（无 src 属性的内联脚本）→ 必须为 0 处
- [ ] HTML 属性搜索 `on[a-z]+=`（onclick/onload 等）→ 必须为 0 处
- [ ] 所有资源相对路径引用，无 http(s):// 外链（图片/字体/数据）
- [ ] localStorage key 加项目前缀（存储按工具隔离，但仍避免与用户其他数据冲突命名习惯）
- [ ] 移动端竖屏 375~430px 宽度适配，触控目标 ≥ 44px
